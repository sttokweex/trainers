# Тренажёры

Два офлайн-тренажёра на одном движке:

- **Собеседование** — 137 вопросов и 27 статей по фронтенду, бэкенду, алгоритмам и архитектуре
- **Аудит** — 83 вопроса, 32 статьи, 29 калькуляторов, 76 карточек и план на 12 недель

Раньше это были два самодостаточных HTML-файла по 12 000 строк с полностью
скопированным движком. Здесь движок написан один раз, а контент подключается
паками.

## Запуск

```bash
pnpm install
pnpm dev            # дев-сервер с HMR
pnpm build          # обычная сборка
pnpm build:single   # всё в один HTML — открывается двойным кликом с file://
pnpm type-check
pnpm test
```

`build:single` нужен, чтобы отдать тренажёр человеку, который не будет ставить
Node: обычная сборка Vite грузит внешний `<script type="module">`, а такой
запрос из `file://` браузер блокирует по CORS. Инлайн-модуль — не блокирует.

## Структура

```
src/
├── engine/        движок: типы, компоненты, раннер, хуки, стили
│   ├── types.ts   форма контента — источник правды
│   ├── runner/    выполнение кода пользователя в Web Worker
│   └── components/
├── demos/         интерактивные демо (пока императивные, переносятся в React)
│   └── helpers/   общий слой: графики, конструкторы упражнений, формат чисел
└── content/       паки контента, по файлу на тему
    ├── interview/
    └── audit/
```

### Типы вопросов

| Тип | Проверка |
|---|---|
| `theory` | нечего проверять — в режиме «Изучение» ответ раскрыт сразу |
| `output` | ответ в пронумерованных ячейках, построчная сверка |
| `code` | код исполняется в воркере и прогоняется через тесты |
| `manual` | сравнение с эталоном вручную |
| `choice` | выбор одного или нескольких вариантов |
| `num` | числовой ответ с допуском |

### Код пользователя

Решения исполняются в **Web Worker** с таймаутом: бесконечный цикл в задаче
прерывается и не вешает вкладку.

Тесты уезжают в воркер через `fn.toString()`, поэтому ассерты (`ok`, `eq`,
`deepEq`, `throwsAsync`, `sleep`) намеренно оставлены **свободными именами**, а
не импортами — иначе минификатор переименовал бы их и воркер получил бы код со
ссылками на несуществующие идентификаторы.

## Перенос контента

`scripts/extract.mjs` — разовый скрипт, вырезавший контент из старых HTML
парсером с балансировкой скобок (корректно пропускает строки, шаблонные
литералы, регулярки и комментарии).

Скрипт пишет только сгенерированные файлы. `src/content/index.ts` и
`src/content/<pack>/index.ts` написаны руками — при повторном прогоне их
удалять нельзя.

## Проверки

`pnpm test` — страховка переноса: счётчики совпадают с исходными файлами,
идентификаторы уникальны, обязательные поля заполнены по типу вопроса, каждое
упомянутое демо зарегистрировано, **198 эталонных решений проходят свои тесты**,
а вопросы на предсказание вывода реально исполняются и сверяются.
