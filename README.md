# Тренажёры

Два тренажёра на одном движке:

| Пак | Вопросы | Статьи | Демо | Ещё |
|---|---|---|---|---|
| **Собеседование** | 168 | 35 | 35 | 10 интерактивов, 47 карточек, план на 8 недель |
| **Аудит** | 111 | 52 | 60 | 46 калькуляторов, 139 карточек, план на 17 недель |

Раньше это были два самодостаточных HTML-файла по 12 000 строк с полностью
скопированным движком. Здесь движок написан один раз, а контент подключается
паками.

## Запуск

```bash
pnpm install
pnpm dev                      # дев-сервер с HMR
pnpm build                    # обычная сборка, паки грузятся лениво
pnpm build:single:audit       # один HTML только с аудитом  (1.2 МБ)
pnpm build:single:interview   # один HTML только с собеседованием
pnpm build:single             # один HTML с обоими паками
pnpm type-check && pnpm lint && pnpm test
```

### Зачем сборка в один файл

Чтобы отдать тренажёр человеку, который не будет ставить Node. Обычная сборка
Vite грузит внешний `<script type="module">`, а такой запрос из `file://`
браузер блокирует по CORS — проверено. Инлайн-модуль не блокирует, поэтому
`vite-plugin-singlefile` решает задачу.

`PACK=<id>` оставляет в сборке только один пак: файл для друга-аудитора не
должен тащить чужой контент. Ветки в `loadPack` написаны так, чтобы бандлер
свернул их по константе из `define` и вырезал лишний пак целиком.

## Структура

```
src/
├── engine/        движок: типы, компоненты, раннер, хуки, стили
│   ├── types.ts   форма контента — источник правды
│   ├── runner/    исполнение кода пользователя в Web Worker
│   └── components/
│       ├── modes/ режимы: практикум, карточки, план
│       └── answers/ по компоненту на тип вопроса
├── demos/         интерактивные демо (пока императивные, переносятся в React)
│   └── helpers/   общий слой: SVG-графики, конструкторы упражнений, формат чисел
└── content/       паки контента, по файлу на тему
    ├── interview/
    └── audit/
```

### Что внутри пака «Аудит»

Учебный маршрут выстроен от механики учёта к аудиторским процедурам:

| Блок | Содержание |
|---|---|
| **Бухучёт** | двойная запись, алгоритм составления любой проводки, справочник типовых проводок, план счетов, закрытие периода, затраты и НЗП, учётная политика, курсовые разницы |
| **Статьи баланса** | разбор каждой строки: из каких счетов собирается, какими проводками наполняется, что проверяет аудитор и где ошибаются. Плюс интерактивная карта баланса, сборка баланса из оборотки и расчёт чистых активов |
| **ФСБУ и налоги** | карта стандартов по годам, ОС и капвложения, запасы, аренда, НМА, НДС, налог на прибыль и ПБУ 18/02, прочие налоги |
| **Аудит** | цикл задания, существенность, риски и предпосылки, доказательства, выборка, внутренний контроль, недобросовестные действия, рабочие документы, процедуры по участкам, завершение и виды мнения |

### Типы вопросов

| Тип | Проверка |
|---|---|
| `theory` | нечего проверять — в режиме «Изучение» ответ раскрыт сразу |
| `output` | ответ в пронумерованных ячейках, построчная сверка |
| `code` | код исполняется и прогоняется через тесты |
| `manual` | сравнение с эталоном вручную |
| `choice` | выбор одного или нескольких вариантов |
| `num` | числовой ответ с допуском |

### Исполнение кода пользователя

Решения уходят в **Web Worker** с таймаутом: бесконечный цикл прерывается и не
вешает вкладку.

Если Worker недоступен — так бывает, когда однофайловую сборку открыли с
`file://`, где блокируются и внешние, и blob-воркеры (проверено), — код
выполняется в главном потоке, и интерфейс честно предупреждает, что защиты от
зацикливания в этом режиме нет.

Тесты уезжают в воркер через `fn.toString()`, поэтому ассерты (`ok`, `eq`,
`deepEq`, `throwsAsync`, `sleep`) намеренно оставлены **свободными именами**, а
не импортами: минификатор переименовал бы импорт, и воркер получил бы код со
ссылками на несуществующие идентификаторы. В тестах они подкладываются через
`Object.assign(globalThis, assert)`.

## Перенос контента

`scripts/extract.mjs` — разовый скрипт, вырезавший контент из старых HTML
парсером с балансировкой скобок: он пропускает строки, шаблонные литералы,
регулярки и комментарии. Заодно проверяет, что модули общего слоя не зовут
хелперы соседних файлов без импорта — иначе демо падает уже в браузере.

Скрипт пишет только сгенерированные файлы. `src/content/index.ts`,
`src/content/all.ts` и `src/content/<pack>/index.ts` написаны руками — при
повторном прогоне их удалять нельзя.

## Проверки

`pnpm test` — страховка переноса: счётчики совпадают с исходными файлами,
идентификаторы уникальны, обязательные поля заполнены по типу вопроса, каждое
упомянутое демо зарегистрировано, **198 эталонных решений проходят свои тесты**,
а вопросы на предсказание вывода реально исполняются и сверяются.

Отдельно прогонялось в браузере: все 33 + 60 демо монтируются без ошибок
консоли (и по отдельности, и внутри статей), все 46 инструментов открываются,
все пять режимов работают, однофайловая сборка открывается с диска.
Отдельная проверка вёрстки на ширине 390 px: горизонтального переполнения нет.

## Состояние кода

Общий слой демо (`src/demos/helpers`) **типизирован и линтуется**: форматирование
чисел, DOM-хелперы, SVG-графики, конструкторы упражнений. Именно здесь уже
проскакивала ошибка «pct is not defined», поэтому скрипт переноса дополнительно
проверяет, что модули не зовут хелперы соседних файлов без импорта.

Стили разложены по назначению (`styles/tokens, header, layout, demos, cards,
editor, article, audit`) и подключаются через `index.css`; порядок важен —
токены первыми, специфика audit последней.

Сами демо перенесены как есть и работают через тонкую обёртку `<Demo>`;
переписывать их в React можно по одному, типы для этого уже готовы.
